命令行程序默认都关联着三条数据流，理解这三条数据流的存在，是理解管道和重定向这两个核心机制的前提。

## 三条标准数据流

每个在终端里运行的进程，默认都会打开三个文件描述符：

- **标准输入（stdin，文件描述符 0）**：程序读取输入数据的通道，默认关联的是键盘输入
- **标准输出（stdout，文件描述符 1）**：程序输出正常结果的通道，默认关联的是终端屏幕
- **标准错误（stderr，文件描述符 2）**：程序输出错误信息的通道，同样默认关联终端屏幕，但和 stdout 是两条独立的流

stdout 和 stderr 虽然默认都显示在同一个终端窗口里，容易被误认为是同一回事，但它们是两条相互独立的数据流，这也是为什么可以单独重定向其中一条、而不影响另一条。

## 重定向:把数据流指向文件

```bash
command > output.txt     # 把 stdout 写入文件,覆盖原有内容
command >> output.txt    # 把 stdout 追加写入文件,保留原有内容
command 2> error.txt     # 把 stderr 写入文件
command > out.txt 2>&1   # stdout 写入文件,stderr 也重定向到同一个文件
command < input.txt      # 把文件内容作为 stdin 输入给命令
```

`2>&1` 这个写法容易造成困惑,含义是"把文件描述符 2(stderr)重定向到文件描述符 1(stdout)当前指向的位置"。书写顺序很关键: `> out.txt 2>&1` 会先把 stdout 指向 `out.txt`,再让 stderr 跟随 stdout 指向同一个位置,最终两条流都写进 `out.txt`;如果写反顺序(`2>&1 > out.txt`),stderr 会先指向此时 stdout 仍然指向的终端屏幕,之后才把 stdout 改指向文件,结果是 stdout 写进文件、stderr 仍然打印在屏幕上。

<Aside type="note" title="/dev/null:数据的终点">
`/dev/null` 是一个特殊设备文件,任何写入它的数据都会被直接丢弃。`command > /dev/null 2>&1` 是常见写法,含义是"丢弃这条命令的全部输出,不管是正常结果还是错误信息",常用在不关心命令输出、只关心是否执行成功的脚本场景中。
</Aside>

## 管道:把一个命令的输出接到下一个命令的输入

```bash
command1 | command2
```

管道符 `|` 的作用是把 `command1` 的 stdout,直接连接到 `command2` 的 stdin,不经过任何中间文件。这让多个功能单一的命令可以组合成更复杂的处理流程,是 Unix 哲学"每个程序只做一件事,做好这件事,通过组合完成复杂任务"的直接体现。

一个常见的实际例子:

```bash
ps aux | grep nginx | wc -l
```

这条命令依次执行:`ps aux` 列出所有进程 → 输出通过管道传给 `grep nginx`,只保留包含 "nginx" 关键字的行 → 结果再通过管道传给 `wc -l`,统计行数。三个命令各自职责单一,通过管道串联后完成了"统计当前运行的 nginx 相关进程数量"这个复合任务。

## 管道与重定向的关系

管道传递的是 stdout,重定向操作的是数据流指向的目标。两者可以在同一条命令中组合使用,例如 `command1 | command2 > output.txt`,表示 `command1` 的输出经过 `command2` 处理后,最终结果写入文件而不是显示在屏幕上。理解这两者各自的作用范围,是读懂复杂命令行组合的基础。
