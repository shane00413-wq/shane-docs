通过 SSH 远程连接服务器执行一个耗时较长的任务时，如果网络断开或者主动关闭了终端窗口，正在运行的程序通常会随之被终止。tmux（Terminal Multiplexer，终端复用器）解决的正是这个问题：它把"正在运行的终端会话"和"当前用来查看它的终端窗口"解耦开，会话本身独立运行在后台，终端窗口断开之后，会话仍然继续运行，之后可以重新连接回去。

## 安装

```bash
sudo apt install tmux
```

## 会话:tmux 的核心概念

会话（Session）是 tmux 里独立运行的一个环境，包含了其中执行的所有命令、正在运行的程序及其状态。会话的关键特性是它的生命周期不依赖于某个具体的终端窗口——启动会话的终端窗口关闭，或者 SSH 连接断开，只要 tmux 服务本身仍在运行（通常在远程服务器上就是持续运行的），这个会话就依然存在，可以之后重新连接回去查看。

```bash
tmux new -s work        # 新建一个名为 work 的会话
tmux ls                  # 列出当前所有会话
tmux attach -t work      # 重新连接到名为 work 的会话
tmux kill-session -t work # 终止指定会话
```

<Steps>
1. 通过 SSH 登录远程服务器,执行 `tmux new -s work` 新建一个会话
2. 在这个会话里启动一个耗时较长的任务(比如一次大规模数据处理)
3. 按下前缀键(默认是 `Ctrl+b`)再按 `d`,从当前会话"脱离"(Detach)——注意这不是关闭会话,任务仍在会话里继续运行
4. 断开 SSH 连接、关闭终端,这些操作都不会影响会话内正在运行的任务
5. 之后重新登录服务器,执行 `tmux attach -t work`,回到之前的会话,任务的执行状态和输出都完整保留
</Steps>

## 前缀键:tmux 内所有快捷键的入口

tmux 内的快捷键都需要先按前缀键（默认 `Ctrl+b`），松开后再按下一个具体按键，两者不是同时按下。这样设计是为了避免和 Shell 本身、或者 Shell 里正在运行的程序的快捷键冲突——只有先按了前缀键，tmux 才会把接下来的按键当作是发给自己的指令，否则会正常传递给当前面板里运行的程序。

## 窗口与面板:会话内部的进一步划分

一个会话内部可以再划分出多个窗口（Window，类似浏览器里的标签页，同一时刻只显示一个）,每个窗口内又可以再划分出多个面板（Pane，同一屏幕内并排显示的多个终端区域）：

| 操作 | 快捷键(先按前缀键) |
| --- | --- |
| 新建窗口 | `c` |
| 切换到下一个/上一个窗口 | `n` / `p` |
| 垂直分割出新面板 | `%` |
| 水平分割出新面板 | `"` |
| 在面板之间切换 | 方向键 |
| 关闭当前面板 | `x` |

<Aside type="tip" title="窗口和面板不是必须掌握才能用 tmux">
如果只是需要"让远程任务在断开连接后继续运行"这一个核心需求,单纯用会话的新建、脱离、重新连接三个操作就已经足够,窗口和面板是在需要同时监控多个任务、或者需要在同一个会话里并排查看多路输出时才会用到的进阶功能,不需要一开始就全部记住。
</Aside>
